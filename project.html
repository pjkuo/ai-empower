🧭 專題工作流Think · Write · Build · Improve

Notion 管「想什麼、為什麼、怎麼學」；GitHub 管「做什麼、改什麼、怎麼跑」。你是專題的主角——自己規劃、自己實作、自己追蹤進度；老師是教練，看你的打卡、在你卡關時出手。

四句口訣

🧠 Notion：想清楚問題是什麼？為什麼值得做？
📝 Notion：寫下來IPO、心智圖、分工、AI 紀錄
💻 GitHub：做出來程式、網頁、資料，進版本
🔄 GitHub：改進它Issue 找問題、PR 改版本

Notion 留下「學習歷程」，GitHub 留下「技術歷程」。

AI × Notion × GitHub 三角

🤖 AI 幫你想發想、解釋、找 Bug；但先自己想，再請 AI 驗證。
📒 Notion 幫你整理把 Prompt、AI 回覆與「你怎麼判斷它對不對」記在計畫頁。
💻 GitHub 幫你實作每次可運作就 commit；AI 給的程式要有你的測試證據。
🪞 Notion 幫你反思這週學到什麼、卡在哪、下週做什麼——回到第一步。

Notion 管「知識」，GitHub 管「作品」；AI 管「協作」，你管「思考與決策」。

👥 四人小組角色（每 3–4 週輪替一次，每個人都要碰到兩個平台）

角色主要工作主平台每週要交出的東西
🧠 A 企劃問題定義、使用者需求、IPONotion計畫頁「問題／需求／IPO」更新

👩‍🏫 老師教練：看打卡、回 Issue、Review PR、評量兩者每週一回覆「需協助」的小組
🧑‍🏫 老師怎麼幫你：每週一看全班的進度打卡，🔴 或勾選「需要老師協助」的小組優先處理（課堂 5 分鐘諮詢或在你的 Issue 留言）。老師不會替你做，但會問你對的問題。

📒 在你自己的 Notion 建學習計畫

計畫頁是你們小組的，放在你們自己的 Notion（學生用學校信箱可申請免費教育方案）。老師只需要一個「可檢視」的連結。

計畫頁 10 個區塊（範本已排好）

  • 專題名稱＋一句話：要幫誰解決什麼問題
  • 1. 問題定義：現況、痛點、為什麼值得做
  • 2. 使用者需求：誰會用？他最在意什麼？
  • 3. 系統架構：感知 → 傳輸 → 分析 → 行動（或前端／後端）
  • 4. IPO：每個功能的輸入、處理、輸出
  • 5. 心智圖：貼圖或連結（心智圖×IPO 單元）
  • 6. AI Prompt 紀錄：Prompt → AI 回覆重點 → 我怎麼驗證 → 採用／修改／不採用
  • 7. 小組分工：本輪 A／B／C／D 是誰
  • 8. 每週進度：W 週次｜完成｜卡點｜下週目標（和「登記與打卡」同步填）
  • 9. 遇到的問題：問題 → 試過什麼 → 怎麼解決
  • 10. 學習反思：期中、期末各一次

分享給老師（10 秒）

計畫頁右上角「分享」→「發布／複製連結」設為知道連結者可檢視 → 貼到「登記與打卡 → 專題登記」。

💻 GitHub 自學實踐：三步開工

  • 建 repo：用老師的專題範本（公布後此處會出現按鈕）或自己新建一個 Public repo
  • 寫 README.md：專題名稱、要解決的問題、如何執行、AI 協作聲明、組員角色
  • 開 GitHub Pages：Settings → Pages → Branch 選 main → 幾分鐘後得到 https://帳號.github.io/repo名/

建議的資料夾結構

smart-irrigation/
├── README.md        ← 專題說明（給人看的首頁）
├── index.html       ← GitHub Pages 首頁
├── css/  js/        ← 網頁樣式與程式
├── python/          ← Python／IoT 程式
├── images/  data/   ← 圖片、資料集
└── docs/            ← 架構圖、測試紀錄

🔄 改進它：Issue → Branch → Pull Request → Review → Merge

🐞 Issue→🌿 Branch→📬 Pull Request→👀 Review→✅ Merge

測試者（D）開 Issue，開發者（C）開分支修正、發 PR，另一位組員或老師 Review 後合併。這就是真正的軟體工程流程。

標題：Bug 01：按下「開始」按鈕沒有反應
重現方式：
  1. 開啟首頁
  2. 按 Start
  3. 畫面沒有更新
預期結果：顯示目前土壤濕度
實際結果：畫面不變，Console 出現 TypeError
環境：Chrome 129／手機 Safari

好的 commit 訊息

feat: 新增濕度低於 30% 自動澆水
fix: 修正 Start 按鈕沒有綁定事件（closes #1）
docs: README 補上執行步驟與 AI 協作聲明
🤖 AI 協作規則：AI 產生的程式可以用，但 PR 說明要寫「哪段是 AI 給的、我怎麼測過」。沒有測試證據的 AI 程式，Review 時會被要求補上。

📌 專題登記 每組一次・組長填

登記後老師的追蹤表只記小組名稱與連結，不記學號；你的身分只用來核對是哪一組。

連結有變動，重新送出即可（以最新一筆為準）。

✅ 每週進度打卡 每組每週一次・誰填都可以

內容和 Notion 計畫頁「8. 每週進度」一致即可。老師每週一看全班打卡，🔴 和「需要協助」優先回覆。
